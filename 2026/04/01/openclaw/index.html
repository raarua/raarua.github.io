OpenClaw 使用随笔：定时任务与 Skill

发表于2026-04-01|更新于2026-05-14|随笔
|浏览量:

最近搭建了 OpenClaw，用下来个人觉得最顺手的是 定时功能：可以把任务交给它在固定时间自动跑，少盯屏幕、少忘事。

定时在解决什么问题

  • 按时间表执行：例如每天上班前汇总、每周一生成周报，不必手动点「运行」。
  • 界面相对直观：调度规则、任务列表往往能在界面上配置和查看，比纯写 crontab 或脚本更易维护。
  • 承接重复性工作：把「每天都要做一遍、步骤又固定」的事交给定时器，把时间留给需要判断力的部分。

一个典型场景：每天自动上传或同步前一天的工作内容（日报、备份、同步到知识库等）。这样不用每天记「别忘了传」，也降低人工维护整套流程的成本。

Skill 与 SKILL.md

Skill 的可复制性和可编辑性很强，可以直接用文本来定义技能。

OpenClaw 里的 Skill 本质上是一份给智能体看的说明，核心就是一个名为 SKILL.md 的 Markdown 文件。你可以在里面写清楚：

  • 目标：这个 Skill 要解决什么问题，成功标准是什么
  • 执行步骤：推荐顺序、分支条件、何时停手
  • 规则与约束：能做什么、不能做什么，以及合规与安全注意点
  • 示例：好的输入输出样例，减少模型“猜”的空间

OpenClaw Agent 可以在运行时写、重载、测试自己的扩展。这也是它看起来比其他 Agent 更“聪明”的一个原因：

  • 遇到不会的操作，可以补一个 Skill 来完成
  • 发现 Skill 有 bug，可以修改并重载
  • 在循环中持续改进自己的工具链

定时负责 何时触发，Skill 负责 触发后按什么套路做。两者搭在一起，比较适合把“重复但又有一定灵活性”的流程固化下来：时间到了自动跑，跑的时候仍按你写在 SKILL.md 里的 SOP 来执行。

若你也在用 OpenClaw，可以把常用流程拆成若干 Skill，再用定时串起来；后面改流程时主要改 Markdown，比散在多处脚本里更好找，也更好审阅。

记忆与日志

OpenClaw 里还有两块比较重要的能力：日志系统和长期记忆。

Daily Logs 日志系统

每天的交互记录会以 append-only 的方式写入 memory/YYYY-MM-DD.md 文件。Session 开始时，Agent 会自动读取今天和昨天的日志，为对话提供连续性上下文。

Long-term Memory 持久化存储

MEMORY.md 是可选的持久化文件，用来存储决策记录、用户偏好和长期事实。

这两部分一起保证了对话的复用和持久记忆。

记忆检索方式

常见的记忆检索方式包括：

  • Embedding 向量：把记忆文本转成向量，计算语义相似度
  • BM25：传统关键词匹配，按词频和权重进行检索

Agent Skill 与 MCP 的区别
Agent Skill 是一份说明文档，用来教大模型「怎么做事」。 MCP 和 agent skill 的区别 MCP（Model Context Protocol） 更像是「给大模型接工具 / 接数据源」。 通过 MCP，可以让模型去访问数据库、HTTP 接口、本地文件等，把外部数据「拿进来」用。 重点是：提供能力 / 数据通道，类似「给模型接各种 API」。 agent skill 是一份纯文档（Markdown），写的是「在某个任务上，你应该按什么步骤做」。 内容包括：任务背景、注意事项、推荐步骤、示例回答等。 重点是：教模型怎么用现有能力来完成任务，类似「给模型写操作手册 / SOP」。 一句话对照 MCP = 插件 / 工具 / 数据源（解决「能做什么 / 从哪拿数据」） agent skill = 使用说明 / 工作手册（解决「拿到数据后要怎么处理、按什么流程做」）
