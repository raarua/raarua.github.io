Agent Skill 与 MCP 的区别

发表于2026-04-01|更新于2026-04-02|随笔
|浏览量:

Agent Skill 是一份说明文档，用来教大模型「怎么做事」。

MCP 和 agent skill 的区别

  • MCP（Model Context Protocol）

    • 更像是「给大模型接工具 / 接数据源」。
    • 通过 MCP，可以让模型去访问数据库、HTTP 接口、本地文件等，把外部数据「拿进来」用。
    • 重点是：提供能力 / 数据通道，类似「给模型接各种 API」。

  • agent skill

    • 是一份纯文档（Markdown），写的是「在某个任务上，你应该按什么步骤做」。
    • 内容包括：任务背景、注意事项、推荐步骤、示例回答等。
    • 重点是：教模型怎么用现有能力来完成任务，类似「给模型写操作手册 / SOP」。

一句话对照

  • MCP = 插件 / 工具 / 数据源（解决「能做什么 / 从哪拿数据」）
  • agent skill = 使用说明 / 工作手册（解决「拿到数据后要怎么处理、按什么流程做」）

harness engineer 是做什么的
harness engineer 可以理解成：把大模型真正接入工程环境，并让它稳定做事的人。 核心关注点和只写 prompt 不同，harness engineer 更关注“模型在真实工程里怎么跑起来”。 常见工作包括： 设计模型可以调用的工具，例如读文件、改文件、跑命令、搜索代码 控制权限边界，避免模型做出高风险操作 处理上下文管理，例如长任务、历史压缩、状态恢复 优化交互体验，例如减少无意义确认、提升执行速度 设计失败恢复机制，让任务中断后还能继续 为什么这个角色重要如果没有稳定的 harness，大模型即使能力很强，也很难在真实开发场景里持续产出。 模型是否“好用”，往往不只取决于模型本身，也取决于： 工具是不是好用 权限是不是合理 错误反馈是不是清晰 状态能不能被保存 长任务能不能持续推进 一句话理解 模型 决定上限 harness 决定落地效果 harness engineer 决定这套系统是否真的可用
